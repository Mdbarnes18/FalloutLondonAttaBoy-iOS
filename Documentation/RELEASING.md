# Release process

All development happens directly on **`main`**. The four platform workflows (IPA, Android, Windows, Linux) run on pushes to `main` and on pull requests targeting `main`.

## Coordinated release gate

A numbered GitHub Release is created automatically once **all four platform workflows succeed for the same `main` commit**. The release job:

1. Confirms successful iOS, Android, Windows and Linux runs exist for the same source SHA.
2. Downloads the eight installable packages.
3. Normalizes asset names to the version in the root `VERSION` file.
4. Generates a SHA-256 checksum file.
5. Publishes one combined release with project-authored notes, package descriptions, installation notes, known limitations and the source revision.

No autogenerated contributor list is included. A version already published is never silently overwritten.

## Versioning

- The format is `major.minor` with a two-digit minor (`1.00`, `1.01`, `1.10`).
- The release history was reset; the clean line begins at **1.00**.
- Bump `VERSION` on `main` when intentionally preparing the next release.

## Package names

For version `X.YY` the release contains:

- `Fallout-London-Companion-X.YY-iOS-unsigned.ipa`
- `Fallout-London-Companion-X.YY-Android.apk`
- `Fallout-London-Companion-X.YY-Windows-Installer.msi`
- `Fallout-London-Companion-X.YY-Windows-Portable.exe`
- `Fallout-London-Companion-X.YY-Linux-x86_64.AppImage`
- `Fallout-London-Companion-X.YY-Linux-amd64.deb`
- `Fallout-London-Companion-X.YY-Linux-x86_64.rpm`
- `Fallout-London-Companion-X.YY-Linux.flatpak`
- `SHA256SUMS-X.YY.txt`

The IPA is unsigned and needs a compatible signing/sideloading workflow. The APK is a debug build.

## Before bumping the version

- All four builds are green on the commit you intend to release.
- The iOS unit-test step is green (not just "passed with errors ignored"). See `build-unsigned-ipa.yml`.
- Known-limitations text in the release notes still matches [README → Status](../README.md#status-what-works-and-what-is-unverified).
